# Member profiles and avatars — 19 November 2026

Added My profile in the header and a signed-in profile shortcut beside the feed. Public profiles show identity, bio, public contribution counts, author-filtered Posts and Answers with pagination, and a listed mentor's availability link. Only the owner sees Edit profile, My sessions, and Mentor studio shortcuts. Email and booking history are not included on public profile pages. Existing author names link to profiles and avatars appear on posts, answers, mentor cards/profiles/recommendations, navigation, and session cards.

All existing and future accounts receive a stored random avatar variant, rendered as a stable illustrated portrait using account ID plus variant. Defaults are local SVG illustrations with no external avatar service, third-party face photos, or added dependencies. The owner can choose another default or upload a PNG/JPEG/WebP photo up to 3 MiB, using the existing public Storage bucket under their own profile prefix. Photos are public by design. The server validates raster signatures; the database validates the referenced object's owner path and existence. Failed uploads are cleaned up; replacing a photo with a default removes the old object. Previously downloaded/cached copies are outside this cleanup guarantee.

Migration `20261119103628_member_profiles.sql` is applied to the hosted project and types were regenerated. The authenticated self-update function derives identity from auth.uid(), uses a pinned empty search path, and keeps direct table writes revoked. It validates display name, normalized unique handle, bio length, variant, and avatar ownership. Public read models use invoker security. The local type refinement reflects nullable avatar paths omitted by function argument introspection.

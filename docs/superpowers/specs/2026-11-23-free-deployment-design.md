# Free portfolio deployment

User authorized Vercel deployment and hosted workers, free-tier only, with Razorpay test keys. This adapts the already approved worker design to scheduled short invocations rather than adding a separate persistent compute service.

Deploy the Next.js app to a personal Vercel Hobby project. Keep the existing hosted Supabase database/auth/storage. A Supabase Cron job calls a POST-only worker endpoint once per minute using an HMAC signature over a timestamp and UUID nonce. The shared secret is in Vault and a server-only Vercel variable; it never enters pg_net's role-readable request queue. Signatures expire after two minutes and a private nonce ledger rejects replay. A bearer-token path is reserved for controlled operator checks. Neither plaintext token nor service keys appear in Git, cron command text, responses or logs. Install pg_cron/pg_net only after the endpoint has been deployed and verified. The schedule calls a private database function that resolves the URL/token from Vault. No Vercel daily cron is used.

The endpoint checks the token before constructing admin clients or running jobs. Short bounded notification and payment batches run independently so an unavailable provider does not block the other. Database leases recover crashed invocations. Test-mode payment guards remain mandatory. There is no real email sending: preview files go to a new private Supabase Storage bucket with service-only access, stable UUID filenames and raster-bucket policies left intact. Local previews remain filesystem-based.

Free tiers have quotas and no always-on guarantee. Supabase may pause inactive free projects; minute-granularity scheduling can deliver later than the nominal reminder time. Do not upgrade plans or add billable services. Production redirect URLs and Razorpay sandbox webhook must use the final deployment origin. Existing accounts/data are preserved and historical notifications are not backfilled.

Acceptance: reject missing/wrong worker credentials without invoking jobs; demonstrate scheduler delivery with laptop workers stopped; verify preview bucket privacy and replay-safe uploads; check deployed login/read/session flows and auth redirects; verify sandbox-only keys, stable webhook reachability, job status and cron history. Real confirmation-email inbox delivery and a new sandbox checkout require separate controlled acceptance; do not infer them from build success.
